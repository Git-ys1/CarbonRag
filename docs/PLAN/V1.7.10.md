# V1.7.10 自动爬虫活跃维护与知识库文件夹化治理

## Summary
- 当前代码已有候选分页、运行分页、`active-maintenance/run` 和“自动爬虫知识库”雏形，但自动维护仍偏手动触发，状态展示不够像任务流水线；KB 侧也缺“文件夹”身份、文档级删除和系统 KB 治理。
- 本轮目标：管理员或 super admin 登录/Relay 在线后，后端静默触发受控自动爬虫维护；同时把知识库升级为“文件夹式 KB”，支持总览、隔离、文档管理、删除和系统自动爬虫 KB 标识。
- 不改 RAG 检索算法，不接 Crawlab 分布式，不打开全局无人在场 `auto_publish`；自动更新只在 admin/super admin 活跃时触发并可观测。

## Key Changes
- 自动爬虫活跃维护：
  - 新增后端“在线触发器”：admin/super_admin 登录成功、管理后台加载、Relay heartbeat 建立或恢复时，静默调用 active maintenance，但必须有冷却时间和分布式锁，避免反复爬。
  - 新增 `policy_crawler_maintenance_runs` 持久化维护记录，记录触发人、触发角色、触发来源、开始/结束时间、状态、抓取源数、候选数、入库数、跳过数、失败数、错误阶段。
  - 维护流程固定为：选择启用源 -> 抓取未更新内容 -> 生成候选与 artifact -> 质量门禁 -> 发布到“自动爬虫知识库” -> quick pipeline -> search smoke -> 写入维护摘要。
  - 跳过原因必须标准化：`cooldown_active`、`source_disabled`、`duplicate_content_hash`、`low_quality`、`small_markdown`、`already_indexed`、`rag_pipeline_failed`、`search_smoke_failed`。

- 自动爬虫状态清晰化：
  - 管理后台“自动更新源”增加顶部状态总览：当前是否正在爬、最近一次维护、最近一次成功、最近一次失败、当前阶段、入库目标 KB、最后错误。
  - 候选表格状态改为分段状态：`已抓取待审核`、`抽取失败`、`重复跳过`、`待入库`、`入库中`、`已入库可检索`、`入库失败`。
  - 每个候选详情抽屉必须显示：抓取文件、Markdown/文本大小、预计片段、RAG 文档 ID、chunk/index 数、search smoke 结果、失败阶段。
  - “自动爬虫知识库”页显示维护流水线，而不是只显示 retry/index/skipped 数字。

- 知识库文件夹化：
  - KnowledgeBaseWorkbench 入口改为“知识库文件夹”视图：每个 KB 是一个文件夹卡片，显示 owner、visibility、系统/个人/共享标识、文档数、chunk 数、最近入库、健康状态。
  - 点击 KB 后进入文件夹详情页：总览、文档、片段、评测、设置五个 Tab；文档表格支持查看、重新解析、重新分块、重新索引、删除。
  - 新增文档级删除能力：删除 RagDocument 时同步删除该文档的 RagChunk、评测引用关系、向量库中对应 doc_id 的向量；不得影响同 KB 其他文档。
  - KB 删除保留现有接口，但加二次确认和保护规则：系统 KB 默认不能普通删除，admin/super_admin 可执行“清空文档 / 重建索引 / 归档”。

- 隔离与系统 KB 规则：
  - private KB 只归 owner 可见；shared KB 可被其他用户检索但不可被普通用户修改；public 预留。
  - “自动爬虫知识库”固定为系统共享 KB，前端显示“系统自动维护 / 管理员只读”；普通用户和普通 AskPage 可检索引用，但不能删除、重命名、手工覆盖。
  - admin/super_admin 可在管理后台对系统 KB 执行：查看文档、删除单个文档、批量清理失败文档、重建索引、运行检索烟测。
  - 为后续转发/分享预留 `kb_scope`、`system_managed`、`share_policy`、`managed_by` 元数据字段，不在本轮做完整分享功能。

## Public APIs / Types
- 新增或稳定：
  - `GET /api/v1/admin/policy-crawler/active-maintenance/status`
  - `POST /api/v1/admin/policy-crawler/active-maintenance/run`
  - `GET /api/v1/admin/policy-crawler/maintenance-runs`
  - `GET /api/v1/admin/policy-crawler/maintenance-runs/{run_id}`
  - `DELETE /api/v1/kb/{kb_id}/documents/{doc_id}`
  - `POST /api/v1/kb/{kb_id}/documents/{doc_id}/rebuild-index`
  - `GET /api/v1/kb/{kb_id}/overview`
- `KnowledgeBase` 增加稳定展示字段：`system_managed`、`managed_by`、`kb_scope`、`document_count`、`chunk_count`、`indexed_chunk_count`、`last_ingested_at`、`health_status`。
- `PolicyCrawlerMaintenanceStatus` 返回：`is_running`、`current_stage`、`last_run`、`last_success`、`last_failure`、`cooldown_until`、`target_kb_id`、`target_kb_name`、`summary`、`warnings`。
- 自动维护触发默认参数：冷却 30 分钟、每次最多 3 个源、每源最多 20 个候选、只处理质量达标候选、失败候选允许重试入库但不重复抓取同 hash。

## Test Plan
- 后端测试：
  - admin/super_admin 在线触发 active maintenance，普通 user 不触发。
  - 冷却时间内重复登录不重复爬取，并发触发只产生一个维护任务。
  - 抓取成功后合格候选进入“自动爬虫知识库”，quick pipeline 后 `indexed_chunk_count > 0`。
  - 抽取失败、低质量、小 Markdown、重复内容、search smoke 失败都写清跳过/失败原因。
  - 删除 KB 文档会删除 chunks 和向量，不影响其他文档；跨用户不能删除他人 private KB 文档。
  - 系统 KB 普通用户可检索不可修改；admin/super_admin 可管理。
- 前端验证：
  - 管理后台进入后无需手动点按钮，状态总览显示“正在检查/最近维护/跳过原因/入库结果”。
  - 候选详情能看清抓取文件、RAG 入库状态、失败阶段。
  - 知识库列表像文件夹，打开后有总览和文档表格。
  - 旧文档和旧 KB 可被有权限用户删除或归档，不再只能堆着。
- 回归命令：
  - `openspec validate crawler-active-maintenance-and-kb-folder-governance --strict`
  - `openspec validate --all`
  - targeted backend tests for crawler/admin/kb/RAG
  - `cd frontend && npm.cmd run typecheck && npm.cmd run build`
  - `git diff --check`

## Assumptions
- 全局 `RAG_POLICY_LIVE_CRAWLER_AUTO_PUBLISH=false` 继续保持；本轮“自动”指 admin/super_admin 活跃时的受控维护，不是无人值守全时定时发布。
- “自动爬虫知识库”本轮账户间共享，普通用户可检索引用；后续再做转发、分享、共享审批。
- 本轮先做同步维护和状态持久化，不引入 Celery、RabbitMQ、MinIO、Crawlab master-worker。
- GitNexus 当前索引 stale，实施前应重建索引；当前探索结果只能作为导航依据。
