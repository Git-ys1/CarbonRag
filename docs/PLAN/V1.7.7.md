# V1.7.7 爬虫管理台重构与受控自动入库

## Summary
- `change-id: crawler-console-compact-table-and-auto-rag-ingestion`。
- 本轮只做爬虫管理台产品化、候选分页表格、详情抽屉、批量发布、受控自动入库和“自动爬虫知识库”闭环。
- 不继续做 super admin，不改 RAG 算法，不扩新增爬虫源，不打开全局 `auto_publish`。

## Key Changes
- 后端把候选和运行记录接口改为分页返回：`items/total/page/page_size`，候选支持 `status/source_id/run_id/rag_pipeline_status/topic_class/query/sort`，运行记录支持 `source_id/status/page/page_size/sort`。
- 新增批量发布接口：`POST /api/v1/admin/policy-crawler/candidates/batch-publish-to-rag`，逐条复用 V1.7.3 的 artifact、质量分、chunk、search smoke 门禁，返回 published/skipped/failed 明细。
- 扩展 `POST /api/v1/admin/policy-crawler/sources/{source_id}/run`，请求体可选 `auto_rag_ingest_enabled` 和门禁阈值；默认仍是手动抓取，不启用全局自动发布。
- 新增“抓取并自动入库”流程：run crawler → candidate quality gate → publish-to-rag → 自动爬虫知识库 → quick pipeline → search smoke → 写入 run summary。
- 统一系统 KB 展示名为“自动爬虫知识库”；兼容旧“官方政策自动更新库”，但前端显示为“系统自动维护 / 管理员只读”。
- 前端重构 Admin 自动更新源页为 4 个 Tab：源库、候选、运行记录、自动爬虫知识库。
- 候选列表改 Ant Design Table，移除 `slice(0, 8)`；运行记录改 Table，移除 `slice(0, 5)`；表格启用分页、固定高度滚动、sticky header、筛选和搜索。
- 新增 `CrawlerCandidateDrawer`，详情抽屉包含：概览、抓取文件、RAG 入库、质量诊断、原始元数据；抓取文件复用现有 `FilePreviewDrawer` 的 `crawler_candidate` 预览。
- 源库 Tab 保留推荐源、自定义源、dry-run，同时新增两个明确按钮：`手动抓取` 与 `抓取并自动入库`。
- 候选表格支持多选批量操作：批量发布到 RAG、批量拒绝、批量重新入库。
- 运行记录表格支持“查看本次候选”，点击后切换到候选 Tab 并设置 `run_id` 过滤。
- 自动爬虫知识库 Tab 显示 KB 状态、文档数、已入库片段数、最近抓取时间、最近入库结果、跳转知识库工作台、检索烟测入口。

## Public APIs / Types
- `GET /api/v1/admin/policy-crawler/candidates` 返回分页 envelope，支持新增过滤参数。
- `GET /api/v1/admin/policy-crawler/runs` 返回分页 envelope，支持新增过滤参数。
- `POST /api/v1/admin/policy-crawler/sources/{source_id}/run` 支持可选 body：`auto_rag_ingest_enabled`、`auto_rag_ingest_min_quality`、`auto_rag_ingest_min_extraction`、`auto_rag_ingest_min_markdown_size`、`auto_rag_ingest_skip_duplicate`。
- `POST /api/v1/admin/policy-crawler/candidates/batch-publish-to-rag` 请求包含 `candidate_ids`、`target_kb_policy=auto_crawler_default`、`skip_duplicates`。
- Run summary 增加：`auto_rag_attempted_count`、`auto_rag_indexed_count`、`auto_rag_failed_count`、`auto_rag_skipped_count`、`target_kb_id`、`target_kb_name`。
- Candidate summary 保持 V1.7.3 字段，并稳定展示 `rag_*`、`artifact_*`、`candidate_quality_score`、`extraction_quality_score`、`topic_relevance_score`、`topic_class`、`skip_reason`、`duplicate_reason`。

## Test Plan
- 后端新增测试：候选分页过滤、运行记录分页过滤、批量发布成功/跳过/失败、低质量候选不能自动入库、重复候选按配置跳过、自动入库 run summary 计数正确。
- 后端新增测试：自动入库必须沿用 V1.7.3 门禁，markdown/cleaned 小于 800、estimated_chunk_count=0、quality<60、quick pipeline zero chunks、search smoke failed 都不得标记 published。
- 前端验证：候选表格不再只显示 8 条，运行记录不再只显示 5 条；详情抽屉能显示 Markdown、纯文本、RAG 状态和元数据；批量操作状态正确。
- 验收流程：导入推荐双碳源 → 对中国政府网政策文件库点击“抓取并自动入库” → 候选表格分页展示 → 详情可查看抓取文件 → 自动爬虫知识库出现新增文档 → AskPage 混合模式可引用。
- 回归命令：`openspec validate crawler-console-compact-table-and-auto-rag-ingestion --strict`、`openspec validate --all`、targeted crawler/admin/RAG tests、`cd frontend && npm.cmd run typecheck && npm.cmd run build`、`git diff --check`。

## Assumptions
- 全局 `RAG_POLICY_LIVE_CRAWLER_AUTO_PUBLISH=false` 继续保持，不因本轮自动入库功能改变。
- “抓取并自动入库”是管理员显式触发的 per-run 行为，不是后台定时自动发布。
- 自动入库目标固定为“自动爬虫知识库”，普通用户可检索引用，但不能删除、修改或手动覆盖该系统 KB。
- 本轮只做同步 quick pipeline，不引入 Celery、RabbitMQ、MinIO 或 Crawlab master-worker。
